# examples/ — 動く最小サンプル

```
examples/
├── demo/          # 架空のイベント。出店者3店、カテゴリ2種、お知らせ3件
│   │              # テーマを当てない素の状態
│   └── variants/
│       ├── ticket/      # チケット運用の確認（設定とデータだけが違う）
│       ├── oneday/      # 1日開催の確認（設定だけが違う）
│       ├── popup-only/  # 商品は店舗からのリンクのみ（設定だけが違う）
│       └── no-items/    # 商品情報なし＝キットの既定（設定だけが違う）
└── demo-default/  # 上とデータも設定も同じで、themes/default/ を当てた状態
```

**見た目を確かめたいなら [demo-default/](demo-default/README.md)、
データの出方を1件ずつ確かめたいなら [demo/](demo/README.md)** を見てください。
どちらも同じデータを使っているので、内容は同じです。

## デモの役割

デモは飾りではなく、**分離できているかの実質的なテストです。**

`themes/` を当てない素の状態で、レイアウトが崩れていても
「データが正しく表示される」ところまで動く必要があります。
素の状態で動かないなら、コアにテーマが混ざっています。

`demo-default/` はその対になるもので、**同じコア・同じデータのまま、
CSSとスロットの並べ方だけで見た目が決まる**ことを示します。
`index.html` 以外はすべて `demo/` と `themes/default/` を共有しているので、
2つを見比べれば、差が見た目だけであることがそのまま分かります。

デモには実在の店舗名・画像・連絡先を入れません。すべて架空のものにします。
