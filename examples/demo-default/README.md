# examples/demo-default — 既定テーマを当てたサンプル

隣の [`demo/`](../demo/README.md) と**データも設定もまったく同じ**で、違うのは見た目だけです。
[`themes/default/`](../../themes/default/) を当てた状態で、実際のサイトに近い形を見られます。

## 動かす

```bash
cd examples/demo-default
python3 -m http.server 8000
```

<http://localhost:8000/?fixed> を開いてください。
`?fixed` は表示順のシャッフルを止めます（付けないと毎回並びが変わります）。

**問い合わせフォームはモックモードで動きます。** 送信すると、実際には送らずに
内容をコンソールへ出して完了表示に切り替わります。PHPを置かずに、
入力・検証・確認モーダルまで確かめられます。

## 何が入っているか

自前で持っているのは `index.html` の1ファイルだけです。残りはすべてリンクで共有しています。

| | どこを見ているか |
|---|---|
| `index.html` | **実体。** `themes/default/index.html` を元にした |
| `css/` | `themes/default/*.css` |
| `images/` | `themes/default/images/` |
| `js/` `i18n/` | `core/js` `core/i18n` |
| `data/` `forms/` `marche.config.json` | `../demo/` と共有 |

**テーマを直すと、このデモにそのまま反映されます。**
シンボリックリンクが使えない環境では、それぞれの中身をコピーしてください。

## テーマの index.html との違い

差分は2箇所だけです。

| 変えたところ | なぜ |
|---|---|
| 出店者スロットの属性値を `stalls` / `foodtrucks` に | `data/shops.json` のカテゴリIDに合わせるため。テーマ側は記入例として `shops` / `foodstores` になっている |
| タイトルとフッターの注記 | 架空のイベントだと分かるように |

**この書き換えは、実際にサイトを作るときにも必ず通る手順です。**
テーマのスロットとカテゴリIDが合っていないと、その区分の出店者は
画面にもエラーにも出ないまま消えます（[docs/setup.md](../../docs/setup.md)）。

フッターの注記のために `.site-note` のスタイルを `index.html` の中に書いていますが、
**これはテーマの一部ではありません。** 既定テーマは
「他の要素を足すときは、その要素が自分の余白を持つ」方針のためです。

## `demo/` との使い分け

| | 役割 |
|---|---|
| [`demo/`](../demo/README.md) | **テーマを当てない素の状態。** コアにテーマが混ざっていないことの検証 |
| `demo-default/` | **テーマを当てた状態。** 実際のサイトの見え方の確認 |

データが正しく出ているかを1件ずつ確かめる表は `demo/README.md` にあります。
**同じデータを使っているので、どちらで見ても内容は同じです。**

設定違いの4パターン（チケット運用・1日開催・商品の掲載範囲）は
`demo/variants/` にあります。こちらは素の状態のままです。

## データの検証

```bash
python3 tools/validate.py examples/demo-default
```

`index.html` のスロットと `data/shops.json` のカテゴリIDが
合っているかも、あわせて確かめられます。

## 実在のものは入っていません

店舗名・紹介文・URL・お知らせはすべて架空です。
画像は動作確認用に生成したプレースホルダで、写真ではありません。
