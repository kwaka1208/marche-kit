# core/ — Halle（市場の屋根）

仕組みの本体。すべてのイベントで共通で、原則として編集しません。

## 構成

```
core/
├── i18n/       # 表示文言の辞書(ja.json / en.json)                    ← 済
├── php/        # 出店者情報の受信・保存、お知らせ書き込み、メール送信  ← 済
├── editor/     # 出店者エディタ、お知らせエディタ                      ← 済
├── js/         # データ取得とDOM組み立て(カード・ポップアップ・フィルタ・シャッフル)
└── components/ # フォームコンポーネント
```

`js/` と `components/` の移植は[段階3](../docs/roadmap.md)で行います。

## コアが守る約束

### 見た目を決めない

**決められたクラス名とDOM構造を出力する。見た目は決めない。**

色・余白・フォントをコアのコードに書いてはいけません。
それはテーマ（[`themes/`](../themes/)）の領分です。
契約の詳細は [docs/theme-contract.md](../docs/theme-contract.md) を参照してください。

例外は [`editor/editor.css`](editor/README.md) です。エディタは来場者が見る画面ではなく
運営と出店者が使う管理ツールなので、テーマの対象外として見た目を同梱しています。

### 文言を直書きしない

画面に出す文字列は `i18n/` の辞書から引きます。
サイト設定の `locale` でどの辞書を使うかが決まります。

| どこから引くか | 書き方 |
|---|---|
| PHP | `marche_text('server.badShopId')` |
| エディタJS | `t('editor.itemName')` |
| エディタHTML | `data-i18n="editor.itemName"` |

`ja.json` と `en.json` は**キー構造を完全に一致させてください。**
辞書を追加するときは既存のキーをすべて埋めます。

`{name}` `{label}` `{max}` `{value}` はプレースホルダで、実行時に置き換わります。

### イベント固有のことを書かない

開催日・カテゴリ・対価の単位・通貨は、すべて `marche.config.json` と
`data/shops.json` から読みます。コードに直接書いてある年・日付・カテゴリ名があれば、
それは移植の漏れです。

### 秘密情報を持たない

通知先メールアドレス・管理キー・Webhook URLを**このフォルダのファイルに書かないでください。**
`.env` に置き、`tools/inject-env.py` が配置先へ流し込みます。
詳細は [php/README.md](php/README.md) を参照してください。

## サーバーとクライアントで揃える定数

画像の上限サイズ・許可拡張子・商品の販売状態は、`php/config.php` と
`editor/editor.js` の両方に定数があります。
**片方だけ変えると、エディタを通ったデータがサーバーで弾かれます。**
