### 移植のときに落としたもの

| 落としたもの | 理由 |
|---|---|
| `srcset` による画像の出し分け | データ仕様では `logo` / `image` は単一のファイル名。2形式の分岐が消えた |
| `allowNameBreaks` と `<br>` の埋め込み | [決定6](decisions.md)。`\n` に統一 |
| カテゴリIDを見た分岐（`category === 'beer'` で接頭辞を変える） | イベント固有。テーマの領分に移した |
| スクロール演出（`reveal-on-scroll`）| 見た目はコアの仕事ではない。代わりに描画完了を `marche:rendered` で知らせる |
| 表示順を固定する `?kotei` | `?fixed` に改名（OSSとして配るため） |

### 分かったこと — 仕様に穴があった

テーマを当てずに動かしてみて、**スロットとクラス名だけでは機能が動かない**ことが分かりました。
開閉するものについて、コアがするのは状態クラスの付け外しだけです。
見せる・隠すの判断はテーマが持ちますが、それが仕様に書かれていませんでした。

| 仕掛け | 無いとどうなるか |
|---|---|
| `*-overlay` を `.active` のときだけ見せる | ポップアップが常に開いたまま見える |
| `[hidden] { display: none !important; }` | 条件に合わない要素が隠れない（`display` を当てた場合） |
| `.faq-item.active` での開閉 | FAQの答えが開いたまま |
| 過去のお知らせの `.is-expanded` | 過去分が最初から見えている |
| `body.no-scroll` | ポップアップの背後が動く |
| 商品グリッドを `grid` にする | 折りたたみが1行分しか描かれない |

この6つを[テーマ仕様](theme-contract.md#テーマが用意する仕掛け)に追記し、
そのまま動く最小形を `examples/demo/mechanics.css` に置きました。
**デモがテーマ無しで動くこと自体が、この一覧が漏れていないことの確認になっています。**

### 分かったこと — 余白は「消えるほう」に持たせる

最初、フッターに `padding` と `border-top` を書いていました。
SNSを設定していないイベントではスロットが隠れるのに、**空のフッターの罫線と余白だけが残りました。**

条件によって消える要素を包むときは、包むほうではなく**消えるほうに余白を持たせます。**
「無い状態で崩れないこと」は[テーマ仕様](theme-contract.md#6-出力されない場合がある要素)に
書いてありましたが、**スロットごと消える要素は初めて**でした（これまでは要素単位）。
一覧に `[data-marche-social]` を足しています。

### 分かったこと — 「見た目が崩れる」で済まない仕掛けが初めて出た

テーマが用意する仕掛けは6つでした。7つ目のハニーポットだけ、性質が違います。

**書き忘れると、来場者の問い合わせが黙って捨てられます。**
コアはおとり欄に値が入っていたらボットとみなし、送信せずに完了したように見せるからです。
画面に出したままだと、来場者が親切に入力して、届かない。しかも**送った本人には成功に見えます。**

実際、確認中に自分で踏みました。ブラウザがフォームの状態を復元したせいで、
**読み込み直後からおとり欄に値が入っていました。** ボットでなくても起きます。
コアの側で、組み立て直後に空へ戻すようにしています（ボットが埋めるのは読み込みのあとなので、検出には影響しません）。

### 分かったこと — スロットを隠すだけでは見出しが残る

段階6でSNSのスロットについて学んだことが、そのまま再発しました。
定義が読めないときスロットだけを隠すと、**「お問い合わせ」の見出しと余白が残ります。**

お知らせが `[data-marche-announcements-section]` でセクションごと隠す仕組みを
すでに持っていたので、同じ形にしました（`[data-marche-form-section]`）。
**新しい作法を増やさず、既にある作法に合わせています。**

## 段階8のあとに足したもの

### 定義とスロットの照合（`tools/validate.py`）

段階8の確認中に、既定テーマにデモのデータを当てて**出店者が0件**になりました。
テーマの記入例（`shops` / `foodstores`）とデモのカテゴリ（`stalls` / `foodtrucks`）が
違うためで、これは**設計どおり**です。カテゴリは設定で定義するもの（[決定1](decisions.md)）で、
テーマに入っている値は書き換えられる前提の記入例です。手順も[配置手順](setup.md)に書いてあります。

**問題は噛み合わないことではなく、噛み合わなかったときに何も起きないことでした。**
コアはスロットが見つからなければ黙って次へ進みます（`core/js/shops.js`）。
これは「要らない機能はスロットごと消せる」という設計の一部で、正しい振る舞いです。
しかし**同じ沈黙が「意図して置かなかった」と「書き忘れた」を区別しません。**
後者では、登録済みの出店者が公開サイトに出ないまま誰も気づけません。

検証ツールが `index.html` を読み、定義に出しどころがあるかを照合するようにしました。
`shops.json` と `shop-data/` の対応を突き合わせているのと同じ形です。

- **見るのは一方向だけ。** 「定義があるのにスロットが無い」＝書いた内容がサイトに出ない状態のみ
- 逆（スロットがあって定義が無い）は**隠れるだけで、意図した運用でも起きる。**
  `examples/demo/variants/` が、まさにそれを確かめるために定義を置いていない
- **コメントの中は数えない。** `themes/default/index.html` には
  「区分が複数あるときはこう書く」という記入例がコメントで入っていて、
  これを実在するスロットと数えると検査が素通りする

### 分かったこと — 検証の守備範囲がデータ側で止まっていた

`tools/validate.py` はデータ同士の対応（ロスターと `shop-data/`、`saleDays` と `days`）を
すべて見ていましたが、**テーマとデータにまたがる対応だけが誰の担当でもありませんでした。**
スロットは Halle と Auvent の接点なので、その両側を見るものが要ります。

### 決着していなかった論点4件（決定14〜17）

[テーマ仕様](theme-contract.md)の「まだ決まっていないこと」に残していた4件に決着をつけました。
**この一覧は空になりました。**

| 論点 | 決着 |
|---|---|
| イベント名・会期・会場を出すスロットが無い | `data-marche-text="<設定のパス>"` を新設（[決定14](decisions.md)） |
| トークン名が色を名指ししている | 8つを役割名に改名（[決定15](decisions.md)） |

**順序に依存がありました。** 決定15（改名）を先に済ませたので、決定16で
「`--surface` に暗色を入れる」ことに説明が要らなくなっています。

### 動作確認したこと

- 設定の差し込み（`site.name` / `event.venue` / `days.label` の連結）が3構成すべてで出ること
- 存在しないパスを指したとき、要素が隠れてコンソールに残ること
- **区切り記号が、どの項目が未設定でも破綻しないこと**（8通りの組み合わせ）
- トークン改名の前後で、描画が1ピクセルも変わらないこと（トークン10個の解決値とスクリーンショット）
- 暗い配色のトークンが12個とも効くこと
- **`<img>` で読むSVGの中でも `@media (prefers-color-scheme)` が効くこと**（Chrome）。
  条件を反転した複製を canvas に描いて画素を読み、3色とも切り替わることを確認した

### 分かったこと — 区切り記号は「見えている兄弟」に付ける

会期・会場・時間を「／」で区切ったところ、**会期が未設定のときだけ先頭に「／」が残りました。**
`hidden` の要素も兄弟としては残るため、隣接セレクタ（`+`）が当たってしまいます。

```css
/* × 先頭が隠れると「／会場名」になる */
.site-meta span + span::before { content: "／"; }

/* ○ 前に「見えている」兄弟があるものだけに当たる */
.site-meta span:not([hidden]) ~ span:not([hidden])::before { content: "／"; }
```

段階6の「余白は消えるほうに持たせる」と同じ問題が、区切り記号という別の形で出ました。
**条件で消える要素を並べるときは、間の装飾をどちらが持つかを毎回確かめる必要があります。**

### 分かったこと — 代替画像だけはCSSの外にある

明暗の切り替えは配色トークンの上書きで足りますが、**`images/noimage/*.svg` だけは届きません。**
`<img>` で読まれるので、ページ側のCSSがSVGの中に及ばないためです。

推測で決めずに測りました。`@media (prefers-color-scheme: light)` を書いたSVGを
`<img>` で読み、canvas に描いて画素を取ると色が切り替わります。**SVGの中に同じ `@media` を
書けば解決する**ことが確かめられたので、コアを変えずに済みました
（`<picture>` で2枚を出し分ける案はコアの変更が要る）。

## v1.0 のあとに足したもの

### 商品情報の掲載範囲を設定で選ぶ（[決定18](decisions.md)）

商品を出すかどうかを決めていたのは、**テーマにスロットがあるかどうか**だけでした。
テーマを掛け替えると、イベントが商品を出すかどうかまで変わってしまう状態です。
「コアはクラス名を出力する。見た目は決めない」の裏返しで、**テーマが運用方針を決めていました。**

`marche.config.json` の `items.display` を `none` / `popup` / `list` の3値にし、
**既定を `none`（掲載しない）**にしました。出店者の紹介だけで完結する催しを素の状態とし、
商品を出すイベントが設定に1行書きます。

- [x] コア（`config.js` / `items.js` / `shops.js`）の分岐
- [x] エディタ — 商品の欄と運営向けの商品関連の一覧を出さない。**登録済みの商品は消さない**
- [x] 隠したセクションを指すナビゲーションの項目も隠す（お知らせ・フォームにも適用）
- [x] テーマ3種に `data-marche-items-section`
- [x] `tools/validate.py` — 設定値の検証、`list` なのにスロットが無い場合の指摘
- [x] 確認用のバリアント2つ（`variants/popup-only/` / `variants/no-items/`）

### 分かったこと — 「隠す」はセクション単体では終わらない

商品のセクションを `hidden` にしても、**ナビゲーションの「商品」は残ります。**
押しても何も起きないリンクです。同じことがお知らせ（0件のとき）と
フォーム（定義が読めないとき）でも起きていました。**先に入れた2つの見落としが、
3つ目を入れるときに初めて見えました。**

テーマは自分がどの設定で使われるかを知らないため、リンクを消せるのはコアだけです。
`hideSection()` を1つ置き、3か所から呼ぶようにしました。

## 意図的にやらないこと

| やらないこと | 理由 |
|---|---|
| npmパッケージ化 | PHPを含み、カスタマイズ前提。テンプレート方式で足りる |
| 管理画面フレームワークの導入 | レンタルサーバーで動く軽さが利点 |

| 承認フロー | 運営がボトルネックになる（[concepts.md](concepts.md)） |
| グリッドの静的化 | 表示順シャッフルの公平性を優先（[concepts.md](concepts.md)） |

| チケットと現金の併用表示 | 実運用に前例がなく、データ構造が複雑になる（[決定5](decisions.md)） |
| i18nライブラリ・言語切り替えUI | 辞書1枚で足りる（[決定4](decisions.md)） |
| 旧形式の読み込み互換 | 切り捨てて構造を単純に保つ（[決定1・2](decisions.md)） |

| Astro（またはビルド工程）の導入 | 問い合わせフォームのために一度検討して却下した。**ファイルを置けば動くことが動作要件**（[決定13](decisions.md)） |
| サポートが終了したPHPへの対応 | 動作要件は**セキュリティサポートが継続しているバージョン**とする（[setup.md](setup.md#動作要件)）。`str_contains()` を `strpos()` に書き換えれば 7.4 でも動くが、**動くことと脆弱性が直されることは別** |
