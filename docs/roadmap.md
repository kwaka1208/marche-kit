### 移植のときに落としたもの

| 落としたもの | 理由 |
|---|---|
| `srcset` による画像の出し分け | データ仕様では `logo` / `image` は単一のファイル名。2形式の分岐が消えた |
| `allowNameBreaks` と `<br>` の埋め込み | [決定6](decisions.md)。`\n` に統一 |
| カテゴリIDを見た分岐（`category === 'beer'` で接頭辞を変える） | イベント固有。テーマの領分に移した |
| スクロール演出（`reveal-on-scroll`）| 見た目はコアの仕事ではない。代わりに描画完了を `marche:rendered` で知らせる |
| 表示順を固定する `?kotei` | `?fixed` に改名（OSSとして配るため） |

### 分かったこと — 仕様に穴があった

テーマを当てずに動かしてみて、**器とクラス名だけでは機能が動かない**ことが分かりました。
開閉するものについて、コアがするのは状態クラスの付け外しだけです。
見せる・隠すの判断はテーマが持ちますが、それが仕様に書かれていませんでした。

| 仕掛け | 無いとどうなるか |
|---|---|
| `*-overlay` を `.active` のときだけ見せる | ポップアップが常に開いたまま見える |
| `[hidden] { display: none !important; }` | 条件に合わない要素が隠れない（`display` を当てた場合） |
| `.faq-item.active` での開閉 | FAQの答えが開いたまま |
| 過去のお知らせの `.is-expanded` | 過去分が最初から見えている |
| `body.no-scroll` | ポップアップの背後が動く |
| 商品グリッドを `grid` にする | 折りたたみが1行分しか描かれない |

この6つを[テーマ仕様](theme-contract.md#テーマが用意する仕掛け)に追記し、
そのまま動く最小形を `examples/demo/mechanics.css` に置きました。
**デモがテーマ無しで動くこと自体が、この一覧が漏れていないことの確認になっています。**

## 意図的にやらないこと

| やらないこと | 理由 |
|---|---|
| npmパッケージ化 | PHPを含み、カスタマイズ前提。テンプレート方式で足りる |
| 管理画面フレームワークの導入 | レンタルサーバーで動く軽さが利点 |
| データベース | 同上。JSONファイルで運用が回っている |
| 承認フロー | 運営がボトルネックになる（[concepts.md](concepts.md)） |
| グリッドの静的化 | 表示順シャッフルの公平性を優先（[concepts.md](concepts.md)） |
| お知らせのクライアントキャッシュ | 古い情報を見せない方を優先（[concepts.md](concepts.md)） |
| チケットと現金の併用表示 | 実運用に前例がなく、データ構造が複雑になる（[決定5](decisions.md)） |
| i18nライブラリ・言語切り替えUI | 辞書1枚で足りる（[決定4](decisions.md)） |
| 旧形式の読み込み互換 | 切り捨てて構造を単純に保つ（[決定1・2](decisions.md)） |
