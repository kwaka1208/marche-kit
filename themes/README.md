# themes/ — Auvent（掛け替える日よけ）

見た目のすべて。イベントごとに自由に作り替えます。

## 構成

```
themes/
├── default/            # 中立な出発点（白背景・上部固定ナビ）
│   ├── index.html      # スロットの見本。コアはここにあるスロットを探して中身を埋める
│   ├── tokens.css      # CSS変数(配色・余白・フォント)
│   ├── layout.css      # セクションとグリッドの配置
│   ├── components.css  # カード・ポップアップ・ナビの見た目
│   └── images/noimage/ # 画像未設定・読み込み失敗のときの代替画像
└── night-market/       # 夜市（暗い背景・下部固定ナビ・画像全面のカード）
```

`default/` は中立な見た目の出発点です。**イベントの色にするときは、
まず `tokens.css` の値だけを差し替えてください。** それだけで雰囲気は変わります。

`night-market/` は**分離できているかを確かめるために作った2つ目**です
（[roadmap.md](../docs/roadmap.md) 段階5）。ファイルの構成は `default/` と同じで、
配色を暗くし、ナビを画面の下に固定し、商品カードは画像を全面に敷いて文字を重ねています。
**コアもDOMも共通のまま、CSSだけでここまで変えられます。**

## 配置する

```
themes/<テーマ>/index.html  → <公開ディレクトリ>/index.html
themes/<テーマ>/*.css       → <公開ディレクトリ>/css/
themes/<テーマ>/images/     → <公開ディレクトリ>/images/
core/js/                    → <公開ディレクトリ>/js/
core/i18n/                  → <公開ディレクトリ>/i18n/
```

コアの `js/` はパス定数でこの配置を前提にしています（[core/README.md](../core/README.md)）。
ビルドは要りません。ファイルを置けば動きます。

## テーマが守る約束

**コアが出力するクラス名にスタイルを当てる。DOM構造を前提にしたJSは書かない。**

テーマとコアが出会うのは**スロット**——テーマがHTMLに置く空の要素で、
コアがそれを探して中身を作ります（[説明](../docs/concepts.md#スロット--halleとauventの接点)）。

テーマがJavaScriptでDOMを組み立て始めたら、それはコアの仕事を奪っています。
テーマ固有の演出（スクロール連動など）はこの限りではありませんが、
**データの描画には触れないでください。**

定義すべきCSS変数の一覧は [docs/theme-contract.md](../docs/theme-contract.md) にあります。

## カテゴリIDに直接スタイルを当てない

コアはカードに `shop-card--<variant>` と `data-category="<カテゴリID>"` の両方を出力します。

```css
/* 推奨: どのイベントでも通用する */
.shop-card--feature { ... }

/* 逃げ道: このイベント専用。他イベントでは当たらない */
[data-category="breweries"] .shop-logo { ... }
```

`breweries` のようなカテゴリIDはイベント固有です。
テーマがそれを知ると、そのテーマは他のイベントで使えなくなります。

## テーマを作る

1. `default/` をコピーして名前を変える（暗い配色なら `night-market/` のほうが近道）
2. CSS変数の値を差し替える
3. レイアウトを調整する
4. テーマ仕様の「コアが探すスロット」がすべて存在することを確認する
5. 「テーマが用意する仕掛け」の7つが書かれていることを確認する
6. `images/noimage/` の代替画像を配色に合わせて描き直す
7. 条件によって出力されない要素（`price-note` など）が無くても崩れないか確認する
8. SNSのリンク（`[data-marche-social]`）を、設定した場合と**していない場合**の両方で見る
9. 問い合わせフォーム（`[data-marche-form]`）を置き、**おとり欄が画面の外にある**ことを確かめる

代替画像（`images/noimage/shop.svg` / `item.svg`）と、
**SNSのアイコンも同じくテーマが持ちます。**
明るい配色のまま暗いテーマに置くと、そこだけ白く光ります。
どこに出るかで決めてください——`night-market/` は、明るい円の中に置くロゴ用は明るいまま、
カード全面に敷く商品用は暗い版にしています。

2つ目のテーマを作って初めて、分離できていない箇所が見つかります。
既定テーマだけで「分離できた」と判断しないでください。
**実際、`night-market/` を作って[コアを1箇所直しました](../docs/decisions.md)**（決定11）。

## 気をつけること

**ハニーポットを画面の外に置く。** 問い合わせフォームのおとり欄（`.courier-honeypot`）です。
**これだけは書き忘れると実害が出ます。** コアは値が入っていたらボットとみなし、送信せずに
完了したように見せるので、画面に出したままだと来場者が入力し、**その問い合わせは届きません。**
しかも送った本人には成功に見えます。`display: none` にしないでください（見分けて避けるボットがいます）。

**開閉はテーマが用意する。** ポップアップ・FAQ・過去のお知らせについて、コアがするのは
状態クラスの付け外しだけです。**見せる・隠すの判断はテーマのCSSが持ちます。**
書かないと、ポップアップが常に開いたまま見えます。必要な7つは
[テーマ仕様の「テーマが用意する仕掛け」](../docs/theme-contract.md#テーマが用意する仕掛け)
にまとめてあり、そのまま動く最小形が
[`examples/demo/mechanics.css`](../examples/demo/mechanics.css) にあります。

**商品グリッドはgridで組む。** コアが `grid-template-columns` を読んで、
折りたたみ時に何件描くかを決めています（列数 × 3行）。flexで段組みすると1行しか出ません。

**`[hidden] { display: none !important; }` を無条件で書く。** 条件に合わない要素を
コアは `hidden` 属性で隠しますが、`display` を当てた要素では効かなくなります。
**URLを登録していない店のポップアップだけが壊れる**、といった見つけにくい形で出ます。

**カード内の重ね順に注意する。** コアは商品カードを「上段 → 画像 → テキスト」の順に出力します。
画像をカード全面に敷くテーマは `z-index` を明示してください
（`position` を与えただけでは、あとに来る画像が上段を覆います）。

**ナビゲーションは上下どちらに固定してもよい。** コアがページ内リンクの着地を補正するのは、
ナビが画面の上端に貼り付いているときだけです。下に固定するときは
`--bottom-nav-height` を実際の高さにして、本文の末尾が隠れないようにしてください。

**SNSのアイコンはテーマが用意する。** コアが出すのはリンクとクラス名
（`social-link--x` など）と表記だけです（[決定12](../docs/decisions.md)）。
同梱の2テーマは表記をそのまま出しています。アイコンにするときは画像を用意して、
[テーマ仕様の書き方](../docs/theme-contract.md#イベント公式のsns)で当ててください。
**各社のロゴにはブランドガイドの条件があります。** 使うサイト側で確認してください。

**スロットごと消える要素は、余白をスロットの側に持たせる。** SNSを設定していないイベントでは、
コアが `[data-marche-social]` を `hidden` にします。包む要素（フッターなど）に
`padding` や `border` を書くと、**中身が消えても罫線と余白だけが残ります。**

**表示の確認は `?fixed` を付けたURLで。** 通常のアクセスでは並びが毎回シャッフルされます。
